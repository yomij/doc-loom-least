# Goal

将 Doc Loom Least 从八个 Skill 组成的阶段工作流，收敛为四个可安装 Skill：
`docloom-workflow` 承担日常开发、状态查询和接续；
`review` 保留明确的复核契约，按用户要求或重要风险触发；
`grill` 保留为用户明确要求时调用的独立追问工具；
`setup-doc-governance` 在需要建立或修复文档治理时使用。
日常流程为“理解目标 → 执行并验证 → 更新必要记录”。
减少路由、重复确认和状态维护，同时保留事实归属、授权边界、验证证据和跨会话接续能力。

本轮合并 `context-authority`、`plan-confirm`、`tdd-execute`、`doc-sync-close`
的必要规则并移除这四个旧入口，不保留转发 Skill 或另一套兼容工作流。
保留 `review` 的决定以 GPT-5.6 的流程可靠性尚未实测为前提；不预设后续必须删除。
保留 `grill` 是用户明确约束，不属于后续精简评估的删除候选。
高后果工作需要与风险匹配的验证和复核，不再与固定文件组合绑定。

目标行为如下：

| 对象 | 完成后的行为 |
|---|---|
| 日常入口 | Agent 在授权范围内直接查证、实现、验证、同步文档；用户无需选择阶段。 |
| 上下文 | 读取相关当前权威和实际实现；历史材料仅作证据；实质冲突得到解决或明确保留。 |
| 任务记录 | 普通一次性任务不建记录。需要接续、保留重要决定或用户明确要求时，每个任务只维护一份 `task.md` 主记录。 |
| 主记录内容 | 目标、验收条件、约束与重要决定、当前进展及下一步、验证证据、最终结果及遗留问题；按需填写，避免空章节。 |
| 状态与接续 | 主记录明确当前状态；暂停或受阻时留下原因和下一步。结束原因区分完成、取消等结果；只有验收成立才可称为完成。状态不再从多份报告的优先级推导。 |
| 辅助材料 | 只有大体量证据或需要独立保留的材料才使用附件；附件不再拥有另一份任务状态。 |
| 授权 | 用户已明确授权的结果和必要实现行为可持续执行；超出授权、改变目标或约束、引入新的重大后果时提出具体决策。恢复任务时核对当前意图及授权适用范围。 |
| 验证 | 按验收条件和实际后果选择证据；重大风险、验证薄弱或用户要求时加强验证和复核。缺失证据不能以完成声明代替。 |
| 复核 | 普通任务完成简短验收检查；重要兼容性、权限、治理规则、实质偏离目标、关键证据缺口或用户要求触发 `review`。对照目标、实际变更和验证结果检查，单独调用 Skill 不自动构成独立判断。 |
| 追问 | 仅在用户明确要求挑战观点或追问假设时调用 `grill`；自行查证可获得的信息，逐个追问关键问题。讨论不自动进入开发流程、建 case、修改文件或批准实施。 |
| 文档同步 | 授权范围内可查证的事实同步由 Agent 完成；改变原则、解决重大冲突或把临时决定提升为长期规则时保留必要的人类决策。 |
| 任务推荐 | 给出推荐项、依据、代价和关键不确定性，取消固定五项打分公式。 |

取消五阶段路由、上下文 verdict 枚举、Direct/Compact/Guarded 成套路径、
按阶段拆分的记录模板、固定七天过期规则和强制两份审查 verdict。
已授权的依赖升级所必需的锁文件变化等，不因文件类别本身再次索取授权。
与具体阶段绑定的提交标记不再成为通用要求；项目提交标题规范继续有效。

# Success Criteria

| Criterion | Evidence required | Status | Evidence |
|---|---|---|---|
| SC1：分发入口由八个减为四个 | 实际可发现的 Skill 名称为 `docloom-workflow`、`review`、`grill`、`setup-doc-governance`；删除四个旧阶段入口后，没有转发壳、失效调用或残留空分组。 | | |
| SC2：日常执行不依赖阶段系统 | 完整读取默认入口及其必读资源后，不需要阶段分派、返回前置阶段、固定路径分类或专门结束阶段；旧规则没有被转移到其他必读文件。 | | |
| SC3：新任务使用可选的单份主记录 | 普通任务不建 case；持续任务用一份 `task.md` 表达目标、状态、证据和接续信息；无条件创建多份报告或推导状态的规则已删除。 | | |
| SC4：授权语义明确且没有降级为默认放行 | 已授权范围内的必要行为不重复确认；授权外动作、约束变化和新的重大后果得到拦截；历史记录或时间流逝不能自动产生授权。 | | |
| SC5：验证和权威规则仍然有效 | 每项验收条件对应实际验证结果或证据位置；未执行的检查标为未验证，不能写成通过；重要风险工作触发明确复核；当前权威、实现证据、历史材料和临时推断的区别明确。 | | |
| SC6：历史 case 可读且可接续 | 旧 case 不批量改写。选取旧完成记录和可恢复记录验证读取；恢复时按当前意图建立单份主记录并引用旧证据，此后只有新主记录承载当前状态，旧记录保留为历史。 | | |
| SC7：公开兼容变化有明确记录 | 新 ADR 明确接替 ADR-0001 中被移除的四个旧名称及相关目录结构的约定；安装说明给出替代方式和升级注意事项，明确 `review`、`grill` 仍可独立调用；不声称既有安装副本已经自动清理。 | | |
| SC8：当前文档与实现一致 | 权威文档、入口、SSOT map、安装指南、中英文介绍、设计说明和当前产品状态描述同一套行为；现行入口不再把旧图示或旧协议当作当前流程。 | | |
| SC9：资源与分发有效 | Skill frontmatter、文档链接、资源路径和发现结果通过检查；四个 Skill 在临时隔离环境的受支持安装方式下均可读取必需资源；不改动用户实际安装。 | | |
| SC10：行为场景覆盖精简后的边界 | 对普通改动、跨会话恢复、已授权依赖升级、授权外不可逆动作、权威冲突、证据不足和历史 case 接续逐一记录输入、预期行为、观察结果及差距；以固定 GPT-5.6 Sol、推理强度和工具条件对照旧流程与四 Skill 方案，关键场景重复运行。静态检查、模拟、历史回放和实际模型运行分别标注，未执行的模型评估不得记为通过。 | | |
| SC11：减少的是总成本而非表面字数 | 同口径记录精简前后默认入口及必读资源的总文本量、所需主记录数量、授权内无必要中断点；新版本总必读文本减少，普通任务零主记录，持续任务一份主记录，授权内不增加无必要中断。 | | |
| SC12：本次变更本身有可信验证 | 以记录的实际基线检查完整变更，包括新增、删除及未提交文件；完成现行要求的 Engineering/Spec 复核，解决实质问题，留下结果与证据。 | | |
| SC13：grill 独立可用且不变成必经阶段 | 用户明确要求追问时可直接使用 `grill`；普通开发任务不自动触发它；重要结论在对话中总结，未经授权不改文件、不建 case、不把简短确认扩展成其他行动的授权。 | | |

# Constraints

- 本次用户请求授权制定和修订计划。v2 纳入 GPT-5.6 能力边界讨论，并记录用户明确要求保留 `grill`；该文件仍为未批准草案，不把讨论、保留偏好或计划请求记作实施批准。

- 变更范围包括 `skills/**` 的入口、规则、模板和资源关系，以及与目标行为直接相关的现行文档。

- 通过新 ADR 明确本轮兼容性决定，并为旧 ADR 增加接替说明；保留旧决策的历史内容、生命周期定位和宪法原则。

- 现有流程图可以退出当前说明并明确作为历史材料保留；不要求重制动画，也不批量修改历史 case 和归档正文。
