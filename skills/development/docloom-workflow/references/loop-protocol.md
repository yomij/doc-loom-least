# Discovery

Candidates are recommendations, not cases or execution authorization. Current
case status comes from shared artifact precedence; the dashboard only helps
locate evidence.

For case continuation, show candidate, status/evidence, next action, and any
needed decision. Do not repair artifacts during discovery.

For next-slice discovery, use `docs/product/current-state.md` or equivalent
current facts: goal, user, demo state, constraints, exclusions, and bottlenecks.
Fill gaps from traceable authority, implementation, or follow-ups; label material
inferences. Ask only for missing facts that could change the recommendation.

Rank useful candidates with the existing rubric:

`Score = Impact + Confidence + Unlock - Effort - Risk`

Each factor is 1–5; Unlock is downstream work enabled. Break ties by higher
Confidence, then lower Risk, then lower Effort. Keep factor detail out of the
default output.

| ID | Slice | Why | Score | Next action |
|---|---|---|---:|---|

Recommend one candidate or none, with a short reason and any material
assumption. Selection returns to normal routing: shared persistence and
assurance rules decide the path; discovery adds no stage or automatic review.
